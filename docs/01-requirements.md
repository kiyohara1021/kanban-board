# 01. 要件・画面

## 機能一覧

### MVP（まずここまで作る）

| 対象   | 機能                                                                   |
| ------ | ---------------------------------------------------------------------- |
| ボード | 一覧表示、作成、名前変更、削除                                         |
| カラム | 追加、名前変更、削除、ドラッグで並び替え                               |
| カード | 追加、タイトル・説明の編集、削除、ドラッグで並び替え、別カラムへの移動 |

### MVP の後に追加した機能

| 対象           | 機能                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------ |
| ラベル         | ボードごとに作る色付きのタグ。作成、削除、カードへの付け外し。カードの一覧とカード詳細に表示する |
| 期限日         | カードごとの期限日（任意）。設定、変更、消去。期限を過ぎたカードを目立たせる                     |
| 検索・絞り込み | ボード画面で、カードを文字とラベルで絞り込む。条件は URL に持つ                                  |

#### ラベル

- ラベルは名前（必須）と色（決まった6色から選ぶ）を持つ。色だけでは見分けにくい人や、読み上げで使う人にも区別できるよう、名前を必ず付ける
- ラベルの作成・削除・付け外しは、カード詳細のモーダルで行う。付け外しはタイトルや説明と同じく「保存」で確定する
- ラベルを削除すると、付けていたすべてのカードから外れる
- 名前や色の変更はまだ扱わない（削除して作り直す）

#### 期限日

- 期限日は時刻を持たない「日付だけ」にする。かんばんのカードは「何日までに」で管理することが多く、時刻まで入れると入力の手間が増えるため
- 期限日の設定・変更・消去は、カード詳細のモーダルで行う。タイトルや説明と同じく「保存」で確定する。カードを作るときには設定しない（作ったあとにカード詳細で設定する）
- カードの一覧では、期限日を「11月5日」のように表示する。今年でない日付は「2027年1月5日」のように年も付ける
- 期限日が今日より前のカードを「期限切れ」として強調する。期限日が今日のカードは、その日のうちはまだ間に合うので期限切れにしない
- 「今日」は、画面を見ている人のパソコンの日付で決める
- 期限切れの強調は、色だけに頼らない。赤い色に加えて「期限切れ」の文字とアイコンを出し、読み上げでも分かるようにする
- かんばんには「完了」を表すカラムの決まりがないので、どのカラムにあるカードでも、期限を過ぎていれば期限切れとして表示する。完了したカードは期限日を消せば強調が消える

#### カードの検索・絞り込み

- ボード画面のヘッダーの下に、検索の入力欄とラベルのボタンを並べる。条件に合わないカードは表示から外す（データは消さない）。サーバーには問い合わせず、取得済みのボードを画面で絞り込む
- 文字の検索は、カードのタイトルと説明が対象。大文字と小文字、全角と半角（「ＲＥＡＣＴ」と「react」など）は区別しない。空白で区切ると、すべての語を含むカードだけが残る
- ラベルは複数選べる。選んだラベルの**どれか1つ**が付いていれば残す。ラベルは「バックエンド」「フロントエンド」のように種類を表すことが多く、複数選ぶときは「どちらかのカードを見たい」場面が多いため（Trello も同じ）。文字とラベルの両方を指定したときは、両方に合うカードだけが残る
- 条件は URL のクエリに持つ（例：`/boards/:boardId?q=react&label=<ラベルの ID>&label=<ラベルの ID>`）。開いているカードと同じく、再読み込みしても条件が残り、URL を共有すれば同じ絞り込みで開ける。カード詳細を開いたり閉じたりしても条件は消えない
- 条件を変えても、ブラウザの履歴には積まない（URL を置き換える）。積むと、戻るボタンで1文字ずつ戻ることになるため
- 日本語入力の変換中は絞り込まない。確定したときに絞り込む（変換中の「ｒ」「れ」のような途中の文字で、表示がちらつかないように）
- 削除されたラベルの ID が URL に残っていても無視する
- 何件見つかったかを、入力欄の横に表示し、スクリーンリーダーでも読み上げる（`aria-live`）
- 絞り込みで1枚もなくなったカラムも表示したまま「条件に合うカードはありません」と出す。カラムの並びや、カードを落とす場所が変わらないようにするため。カードを隠しているカラムには、隠している枚数も出す（絞り込み中に追加したカードが条件に合わず、消えたように見えるのを防ぐ）
- 絞り込み中も、ドラッグ&ドロップでカードを並び替えられる。並び順は隠れているカードも含めて計算し、表示している並びのとおりに保存する。隠れているカードとの前後は、下へ動かしたときは重ねたカードの直後、上へ動かしたときは直前になる（[04-frontend.md](04-frontend.md#カードの検索絞り込みmvp-の後に追加)）
- カラムの見出しの枚数と、カラムの削除の確認に出る枚数は、隠れているカードも含めた枚数のまま（削除すると隠れているカードも消えるため）
- 期限日での絞り込みは、まだ扱わない

## 画面

| パス                             | 画面                   | 内容                                                                       |
| -------------------------------- | ---------------------- | -------------------------------------------------------------------------- |
| `/`                              | ボード一覧             | ボードの一覧と新規作成フォーム                                             |
| `/boards/:boardId`               | ボード                 | カラムとカードの表示、追加、ドラッグ操作                                   |
| `/boards/:boardId/cards/:cardId` | カード詳細（モーダル） | ボード画面の上にモーダルを重ねて、タイトル・説明・ラベル・期限日を編集する |

カード詳細を開いているかどうかを URL で表すと、リロードしても開いたままになり、URL を共有することもできる。絞り込みの条件も、同じ理由で URL のクエリ（`?q=…&label=…`）に持つ。ボードとカード詳細のどちらの URL にも付けられる。

## MVP では扱わないこと

- 認証（誰でも全ボードを操作できる）
- 同時編集の衝突対策（最後に保存したものが残る）
